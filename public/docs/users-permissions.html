Users & Permissions

NetherPanel has a built-in user system with roles, forced password changes, server-level sub-user permissions and API tokens.

Registration

New users can register through the login page at http://localhost:3000. By default, open registration is allowed — you can disable it in the admin Settings panel.

New accounts are regular users with no server access by default.

Roles

RoleCan do
AdminFull panel access: create servers, manage all users, view/stop other people's servers, change settings
UserSee only their own servers; no admin panel access
Sub-userPermissions granted on a specific server by the owner or an admin (e.g. "can start/stop", "can see console")

Creating admin users

From the CLI

bash
node create-admin.js <username> <password> [email]

From the admin dashboard

Admin → Users → Add User. You can optionally set must change password so the user is forced to pick a new one on first login — same as the default admin account on first boot.

Default admin credentials are admin / admin123. The panel forces a password change on first login. Do it.

Sub-user permissions

A server owner can add sub-users to specific servers. Each sub-user can be given fine-grained permissions per server, for example:

  • Console access (view + send commands)
  • Start / stop / restart
  • File manager access
  • Backup management

An admin can also assign sub-user permissions to any server.

API tokens

Users can generate personal API tokens to call the panel REST API externally (e.g. for Discord bots or automation scripts). Tokens are created from the user's account page and are tied to their role permissions — a sub-user token can only hit endpoints they have access to.

Security notes

  • Server path and pid are hidden from non-owner/non-admin responses to prevent information leakage.
  • Only the server owner or an admin can delete a server.
  • JWT tokens are used for session management; the panel uses bcrypt for password hashing.
