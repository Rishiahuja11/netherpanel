Configuration & Environment

NetherPanel uses a SQLite database and a handful of environment variables. Most settings are editable live from the admin Settings panel.

Environment variables

These can be set in your shell, in .env, or passed inline when starting the panel:

VariableDefaultDescription
PORT3000Port the panel web server listens on
NETHERPANEL_HOSTauto-detectedOverride the public IP advertised in server addresses and share links (e.g. for VPS or LAN setups)
NETHERPANEL_DBdata/netherpanel.dbPath to the SQLite database file
NETHERPANEL_DATA_DIRdataRoot data directory (servers, backups, databases)
example — change the port
PORT=8080 npm start
example — advertise a VPS public IP
NETHERPANEL_HOST=203.0.113.42 PORT=3000 npm start

Database

NetherPanel uses better-sqlite3 (synchronous, file-based SQLite). The database file lives at data/netherpanel.db. There is no external database server to install or manage.

The database schema includes:

  • users — accounts, roles, hashed passwords, must_change_password flag
  • servers — created servers, owner, config, resource caps, status, crash stats
  • settings — key-value panel settings (panel_name, registration_enabled, etc.)
  • api_tokens — user API tokens for external integrations
  • schedules — cron jobs per server

Migrations run automatically on startup — no manual SQL needed.

Admin Settings (in-panel)

All key-value settings are editable live from the admin Settings tab. Changes take effect immediately — no restart needed. See the Admin Panel page for a full list of editable settings.

Data directory layout

data/
data/
├── netherpanel.db          # SQLite database
├── servers/                # One subdirectory per server
│   └── my-paper-server/
│       ├── server.properties
│       ├── world/
│       └── ...
├── backups/                # Backup archives
└── pmmpphp/                # PocketMine PHP runtime (auto-downloaded)

Security notes

  • Server path and pid fields are stripped from API responses for non-admin, non-owner users.
  • Only server owners and admins can delete servers.
  • Subdomain values are validated with a strict regex (/^[a-z0-9]([a-z0-9-]{0,61}[a-z0-9])?$/) to prevent injection.
  • Panel start uses a self-contained pid-file stop (no fuser -k or broad pkill) to avoid killing unrelated processes.
